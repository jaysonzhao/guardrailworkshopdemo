= Guardrails for a banking agent on OpenShift

A customer who asks how to reset a password should get instructions. A customer who types a one-time password into the same chat should get a privacy refusal. You will deploy a LangGraph banking assistant, make that distinction in NeMo Guardrails, and test it through the application your customers would use. All accounts, balances and credentials in the exercises are fictional.

== Your environment

Each participant signs into a dedicated OpenShift project. The hosted Terminal includes a matching OpenShift CLI, Python, PyYAML, curl and the executable workshop CLI. A local Linux or Dev Spaces terminal is also supported. The project needs OpenShift Builds with Docker strategy, the integrated image registry, Routes, and a network plugin enforcing Kubernetes NetworkPolicy. Binary builds need access to the Red Hat UBI images, UBI RPM repositories for the proxy build, and the Python package index. The main model must offer OpenAI-compatible chat completions and tool calling, with an endpoint reachable from the pods. Have the model's serving ID, its base URL ending in `/v1`, its credential, and the MaaS subscription name if required.

Pre-1 through Module 2 and Module 4 can use a remote MaaS model and need no GPU in your lab project. Only Module 3 provisions model weights. It requires one available BF16-capable NVIDIA GPU with enough free memory for the 8B model, a working GPU device plugin, a 30 GiB RWO PVC, access to the serving image and weights, or a prepopulated cache.

== Open your workspace

Open the Showroom HTTPS URL supplied by your instructor. Select your normal cluster identity provider, sign in and approve the requested project access on first use. The guide stays on the left. The *Terminal* tab starts a shell in a writable copy of the lab. The *OCP Console* tab opens the cluster console with the same identity provider. On clusters configured for embedding it appears beside the guide. On other clusters it opens in a browser tab. An existing cluster browser session can be reused.

In *Terminal*, run the following. Confirm that the username matches the console's user menu and the project matches your assignment. The Run button on marked command blocks sends the command to this terminal. Enter examples that contain your own values manually.

[source,bash,role="execute"]
----
oc whoami
oc config view --minify -o 'jsonpath={.contexts[0].context.namespace}{"\n"}'
./grlab --help
----

Edits under `/workspace/lab` survive switching tabs and reconnecting to the same pod. Export your work before the instructor replaces the pod. Shell variables belong to each connection. Open *Banking playground* above the guide after Pre-1 deploys the application.

== Use your own terminal

Download xref:attachment$lab-files.zip[the participant code ZIP] while signed in. The hosted Terminal already contains these files. For a laptop or Dev Spaces workspace, extract the ZIP, change to `guardrail-agent-lab/` (or `guardrail-agent-showroom/` from the full ZIP), and use an authenticated OpenShift CLI. Use Python 3.10 or newer.

[source,bash]
----
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt
./grlab --help
oc whoami
----

If an extraction tool discarded Unix permissions, run `chmod +x grlab` once. The local HTML preview provides the guide. Sign in through the deployed Route to use the hosted tabs and Run controls.
